# NFL projection review — staging only

Run the isolated interface with `streamlit run app_nfl_staging.py`. Do not treat this as a live optimizer.

The original DAILY exports have a labeled 20-column offensive header; the DST and kicker records use shorter layouts without their own header. Both actual November 25 and 26 exports contain these records. All eight DST score candidates are consistent with their stated fantasy value per $1,000 to within ordinary display rounding (maximum absolute score residual 0.02). That is structural corroboration, not authoritative provider schema confirmation. Kicker rows lack numeric salary/value; do not infer kicker scores from unrelated players. Until the provider schema is explicitly verified, these numbers remain unlabeled candidates, not trusted scores.

The independent review accepts a JSON list with exact contest-scoped player_id, contest_id, slate_date (YYYY-MM-DD), team, game, scoring ("FanDuel"), source, source_family, source_record_id, independence_reviewed (true only after genuine independent-origin review), asof_utc, observed_at and projection_fd. No source records or timestamps are synthesized. Both timestamps must be at or before the cutoff; the default publication freshness limit is 24 hours. Repeated source families count once; conflicting scores within a family are held for review. Two independently reviewed families must agree within max(2 FD, 20% of median) to produce a provisional review consensus. This tolerance is a conservative experimental diagnostic, not historically calibrated and not a promotion criterion.

Existing DAILY scores remain unchanged, missing values remain explicit, and review output never certifies eligibility, full-pool scoring, or a live lineup. Actuals and post-cutoff evidence cannot be used to reconstruct pre-lock forecasts. Source registry is shown without falsely marking manual sources checked. Hosted verification, source acquisition and optimizer integration remain outstanding.

## Fixed-candidate integration

The isolated NFL staging preview also accepts a JSON bundle containing slate_date, cutoff_utc, salary_cap, daily_capture, evidence and candidates. The DAILY capture must explicitly reference the exact raw export SHA-256, contest ID, slate date, observed_at, source_record_id and reviewed=true. A cutoff within 24 hours of capture is required; this is an experimental freshness rule, not authenticated proof. Missing eligible scores can be evaluated using the independently corroborated advisory consensus, never the unlabeled special-teams candidate alone. Conflicts and unresolved eligible scores block every ranking.

Classic candidate records require candidate_id, contest_id, slate_date, created_utc and the exact nine-slot map (QB, RB1, RB2, WR1, WR2, WR3, TE, FLEX, DEF). Single-game candidates require the same identity/time fields plus six roster_ids and an explicit mvp ID. The underlying validators check salary, position, uniqueness and explicit MVP pricing. The supplied cap and official contest team-count/other rules still require external confirmation; no full legality or official status certification is asserted. No lineup generation, automatic scoring change, release, or live slate use.
